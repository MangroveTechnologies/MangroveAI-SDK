# Oracle OpenAPI contract snapshot

`oracle-openapi.json` is generated by Oracle's FastAPI `app.openapi()` from the
Oracle source commit recorded in `oracle-openapi-provenance.json`. The refresh
imports the app but does not start its lifespan or make service, database,
market-data, or billing calls. Keep the schema and provenance files together.

To refresh it from an Oracle and MangroveAI source checkout with their Python
dependencies installed:

```sh
python scripts/refresh_oracle_openapi.py \
  --oracle-source /path/to/MangroveOracle \
  --mangroveai-source /path/to/MangroveAI
python scripts/check_oracle_openapi_contract.py
```

To verify a refresh without changing tracked files, pass the same source paths
with `--check`. It fails if either checkout is dirty or if the generated schema
or source provenance differs from the reviewed files.

CI runs the deterministic model check against the reviewed snapshot. It checks
request/response field names and requiredness, types, nullable values, enums,
defaults, bounds, arrays, and nested references for the data-query operation.
Nullable unions and the schema's unconstrained filter value are handled
explicitly; unsupported schema composition fails closed. It is a first bounded
guard for SDK issue #21, not full OpenAPI code generation or coverage of every
Oracle operation. When Oracle changes this contract, refresh from the intended
Oracle source revision, review the generated diff, update SDK models as needed,
and commit both snapshot files.
